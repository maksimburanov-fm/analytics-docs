# Freedom Media Events Documentation

## Общее описание

Этот репозиторий содержит документацию событийной модели Freedom Media.

Документация покрывает только события, которые настроены и отправляются через **Google Tag Manager** для web-зоны `fmedia.kz`.

Событийная модель охватывает:

* веб-приложение Freedom Media на desktop;
* веб-приложение Freedom Media в мобильном браузере;
* адаптивную web-зону Android-приложения;
* миниапп Freedom Media внутри Freedom SuperApp;
* отдельные webview-сценарии внутри iOS native app, если пользователь попадает в web-зону `fmedia.kz`.

Важно: все эти сценарии технически работают через web или webview. Поэтому платформу нельзя определять только по факту наличия события. Для корректного анализа нужно учитывать URL, Page Location, параметры страницы и источник отправки события.

---

## Состав документации

Документация состоит из нескольких таблиц и словарей.

| Таблица / словарь           | Назначение                                             |
| --------------------------- | ------------------------------------------------------ |
| `Triggers`                  | Справочник GTM-триггеров и условий их срабатывания     |
| `trigger_parameters`        | Технические параметры GTM-триггеров                    |
| `Tags`                      | Связка GTM-тегов, событий и триггеров                  |
| `Tags_Params`               | Параметры, которые передаются в событиях               |
| `dictionary`                | Словарь технических и унифицированных названий событий |
| `event_descriptions_lookup` | Описание унифицированных событий                       |

---

## Связи таблиц и словарей

Основная логика модели:

```text
Triggers → Tags → Tags_Params
              ↓
          dictionary → event_descriptions_lookup
```

Рекомендуемые связи:

| Левая таблица | Левая колонка      | Правая таблица              | Правая колонка         | Направление фильтрации                   | Тип связи |
| ------------- | ------------------ | --------------------------- | ---------------------- | ---------------------------------------- | --------- |
| `Triggers`    | `triggerId`        | `Tags`                      | `firingTriggerId`      | `Triggers → Tags`                        | `1:*`     |
| `Tags`        | `tagId`            | `Tags_Params`               | `tagId`                | `Tags → Tags_Params`                     | `1:*`     |
| `Tags`        | `eventType`        | `dictionary`                | `technical_event_name` | `dictionary → Tags`                      | `1:*`     |
| `dictionary`  | `unified_event_id` | `event_descriptions_lookup` | `unified_event_id`     | `event_descriptions_lookup → dictionary` | `1:*`     |
| `Triggers`    | `triggerId`        | `trigger_parameters`        | `triggerId`            | `Triggers → trigger_parameters`          | `1:*`     |

Если в `dictionary` есть несколько технических названий для одного унифицированного события, основной аналитический ключ — это `unified_event_id`.

## Особенность определения платформы

Так как desktop web, mobile web, Android adaptive zone, SuperApp miniapp и часть iOS webview-сценариев используют один и тот же домен `fmedia.kz`, платформу нужно определять по дополнительным признакам.

Один и тот же сайт может быть открыт:

* как обычный desktop web;
* как mobile web в браузере;
* как webview внутри Android-приложения;
* как miniapp внутри Freedom SuperApp;
* как webview внутри iOS native app.

Поэтому при анализе событий важно смотреть не только на `event_name`, но и на:

* Page Location;
* Page URL;
* Page Path;
* параметры URL;
* источник события;
* категорию отправки события.

## Событие `start_page`

Для определения точек входа на платформу есть событие `start_page`. Оно срабатывает при первой загрузке страницы. 
В него передается параметр is_sa = 1, которое позволяет определить, что человек попал на платформу через SupaerApp. 

Также в него передается Page Path, которое позволяет определить, на какую страницу попал пользователь при переходе.

## Page Viewed и системные просмотры страниц

Дополнительно в Amplitude, Google Analytics и Яндекс Метрику передаются системные события просмотра страниц.

В Amplitude используется системное событие:

```text
Page Viewed
```

По параметру `Page Location` в Amplitude или URL/page location в Google Analytics можно определить, откуда пользователь открыл web-зону.

Пример захода через адаптивный Android App или определенных зон нативного приложение iOS, где прогружается вебвью:

```text
https://fmedia.kz/?device_serial=00157993
```

В этом случае параметр `device_serial` может указывать на открытие Android-приложения или web-зоны iOS-приложения .

Пример захода через Freedom SuperApp:

```text
https://fmedia.kz/?language=en&theme=dark
```

В этом случае параметры `language` и `theme` могут использоваться как признаки открытия web-зоны внутри SuperApp.

Также часть посещений может собираться из iOS native app, если пользователь попадает в webview-зону для отдельных функций. Поэтому при анализе нужно явно фиксировать платформу и не смешивать mobile web, Android app, iOS webview и SuperApp miniapp без дополнительной проверки.

## SuperApp и miniapp Freedom Media

События SuperApp появляются только после того, как пользователь перешел в миниапп Freedom Media внутри Freedom SuperApp.

У SuperApp есть собственная аналитическая инфраструктура: Amplitude и AppsFlyer. Для передачи событий из miniapp Freedom Media в аналитику SuperApp используется JS bridge, вызовы которого настраиваются через GTM.

В документации такие события выделяются как отдельные категории:

```text
SuperApp Amplitude bridge
AppsFlyer SuperApp bridge
```

Эти категории не являются обычными web-событиями сайта. Это события, которые web-зона Freedom Media отправляет во внешнюю аналитику SuperApp через bridge.

---

## Трекеры и системы аналитики

Через GTM события могут отправляться в следующие системы:

* Amplitude Freedom Media;
* Google Analytics;
* Яндекс Метрика;
* SuperApp Amplitude через JS bridge;
* AppsFlyer SuperApp через JS bridge;
* внутренний ClickStream / event API, если событие настроено для внутренней отправки;
* рекламные пиксели и внешние маркетинговые трекеры, если они подключены в контейнере.

## Унифицированные названия событий

Одно и то же пользовательское действие может иметь разные технические названия в разных источниках.

Например, web-событие, событие для SuperApp Amplitude bridge и событие для AppsFlyer SuperApp bridge могут описывать один и тот же пользовательский шаг, но иметь разные `event_name`.

Поэтому в документации используется слой унификации:

```text
technical_event_name + source/platform → unified_event_id
```

`unified_event_id` — это стабильный аналитический ключ события.

Технические названия событий могут отличаться между системами, но `unified_event_id` должен позволять объединить их в единую событийную модель.

## Правила работы с документацией

Технические таблицы, которые описывают GTM-теги, триггеры и параметры, не должны редактироваться как бизнес-словарь.

Ручное ведение нужно для следующих сущностей:

* унифицированные названия событий;
* описание событий;
* соответствие web-событий и SuperApp-событий;
* описание параметров;
* правила определения платформы;
* статусы событий;
* комментарии и спорные места.

## Как использовать документацию

Документация должна помогать отвечать на вопросы:

* какие GTM-события настроены для Freedom Media;
* какие теги отправляют событие;
* какие триггеры запускают событие;
* какие параметры передаются;
* в какие системы аналитики отправляется событие;
* какое техническое название события используется в конкретной системе;
* какому `unified_event_id` соответствует техническое событие;
* как определить платформу пользователя;
* какие события относятся к web, SuperApp bridge, AppsFlyer bridge или системным просмотрам страниц.

## Основной принцип модели

Нельзя считать, что одно техническое `event_name` полностью описывает бизнес-событие.

Корректная модель строится так:

```text
GTM trigger
  → GTM tag
  → technical_event_name
  → source/platform
  → unified_event_id
  → event parameters
  → business description
```

Такой подход позволяет поддерживать единую событийную документацию для desktop web, mobile web, Android webview, iOS webview и SuperApp miniapp.

# Analytics Documentation

Репозиторий для хранения документации по аналитике продукта Freedom Media.

## Назначение

Проект нужен для системного описания аналитики продукта:

* событийной модели;
* GTM-контейнера;
* параметров событий;
* триггеров;
* метрик;
* дашбордов;
* источников данных;
* справочников и маппингов.

Документация хранится в Git, чтобы сохранять историю изменений и вести её в едином формате.

## Разделы

### `docs/`

Текстовая документация по аналитике:

* общее описание аналитической системы;
* событийная модель;
* описание метрик;
* описание Power BI-дашбордов;
* описание GTM;
* описание источников данных.

### `gtm/`

Материалы по Google Tag Manager:

* экспортированные версии GTM-контейнера;
* описание изменений;
* заметки по тегам, триггерам и переменным.

Экспорты контейнера хранятся в формате JSON.

### `events/`

Таблицы событийной модели:

* `events.csv` — основной справочник событий;
* `event_params.csv` — параметры событий;
* `event_aliases.csv` — связь разных названий событий с единым `event_id`;
* `triggers.csv` — условия отправки событий.

### `dictionaries/`

Вспомогательные справочники:

* платформы;
* группы событий;
* владельцы разделов и сущностей.

## Основной принцип событийной модели

У каждого логического события должен быть стабильный `event_id`.

Фактическое название события может отличаться между платформами, например web, mobile app или SuperApp. Такие различия фиксируются в `events/event_aliases.csv`.

## Форматы хранения

* Markdown — для текстовой документации.
* CSV — для справочников и таблиц.
* JSON — для экспортов GTM-контейнера.

## Правила работы

1. Одно логическое изменение — один коммит.
2. Название коммита должно кратко описывать изменение.
3. Перед коммитом нужно проверять изменения через `git diff`.
4. GTM-экспорты перед добавлением в Git нужно проверять на наличие токенов, ключей и чувствительных данных.
5. Справочники событий и параметров нужно поддерживать в актуальном состоянии.

# spark_dm.full_catalog

## Назначение

`spark_dm.full_catalog` - витрина каталога контента OTT-сервиса. Она нормализует родительские карточки контента и дочерние элементы каталога, чтобы аналитика могла связывать VOD-просмотры с метаданными: названием, типом контента, библиотекой, страной, годом, рейтингами, правообладателем, производством, сезоном и эпизодом.

Витрина используется для аналитики потребления контента, сегментации пользователей по просматриваемому контенту, построения BI-витрин и обогащения `spark_bsns_vlt.msp_content_session` по `content_id`.


## Гранулярность

Одна строка = одна контентная единица с уникальным `content_id`.

В зависимости от типа и связей это может быть:

- фильм или standalone-контент из родительского каталога;
- сериал/родительская карточка;
- эпизод или дочерняя единица сериального контента;
- контентная запись без найденного родителя, отмеченная через `data_quality`.

По агрегатной проверке в витрине 44 157 строк и 44 157 уникальных `content_id`.

## Источники данных

- `spark_bsns_vlt.msp_ref_catalog_content` - родительский каталог контента. Из него берутся основные метаданные: названия, библиотека, год, тип, рейтинги, правообладатель, production, страны, признак трейлера.
- `spark_bsns_vlt.msp_ref_child_catalog_content` - дочерний каталог. Из него берутся дочерние `content_id`, `top_parent_id`, сезон, эпизод и дочернее оригинальное название.
- `spark_bsns_vlt.vw_full_catalog` - промежуточное представление в БД, в котором описана логика объединения parent/child. Судя по фактической схеме, `spark_dm.full_catalog` материализует его результат и добавляет техническое поле `t_v_crdate`.
- `spark_bsns_vlt.vw_catalog_content` - дополнительное представление каталога, которое объединяет родительский каталог с сезонами и эпизодами через `FULL JOIN`. В фактической логике `vw_full_catalog` напрямую не использует это view, но оно отражает близкую parent/child-нормализацию.

## Логика формирования

Подтвержденная логика из `spark_bsns_vlt.vw_full_catalog`:

- CTE `parents` берет записи из `spark_bsns_vlt.msp_ref_catalog_content`.
- Для родительского каталога применяется `row_number() over (partition by content_id order by start_date desc)` и оставляется `rn = 1`. Так выбирается последняя по `start_date` версия метаданных на каждый `content_id`.
- CTE `childs` агрегирует `spark_bsns_vlt.msp_ref_child_catalog_content` по `content_id` и `top_parent_id`.
- Для дочерних записей рассчитываются:
  - `child_original_title = max(original_title)`;
  - `season = max(season)`;
  - `episode = max(episode)`.
- Основное объединение: `parents p full join childs c on p.content_id = c.top_parent_id`.
- `content_id` итоговой строки рассчитывается как `coalesce(c.content_id, p.content_id)`.
- `top_parent_id` рассчитывается как `coalesce(c.top_parent_id, p.content_id)`.
- Метаданные контента (`content_title_ru`, `original_title`, `library`, `type`, `countries`, `production`, рейтинги и др.) берутся из родительской записи `p`.
- Для дочерних записей сезон, эпизод и `child_original_title` берутся из агрегата `childs`.
- Поле `data_quality` классифицирует результат объединения:
  - `child_without_parent` - дочерняя запись есть, но родительская карточка не найдена;
  - `child_without_id_parent` - у дочерней записи не определен `top_parent_id`;
  - `parent_without_child` - родительская карточка есть, но дочерних записей нет, и тип не `movie` или тип пустой;
  - `normal` - остальные записи.

В фактической витрине `spark_dm.full_catalog` нет колонок `genres` и `themes`, хотя они есть в исходных catalog-объектах. Поэтому анализ жанров и тем напрямую по этой витрине невозможен без обращения к source/view, где эти поля сохранены.

## Нормализация контента

Витрина объединяет родительский и дочерний уровни каталога.

- Родительский уровень (`msp_ref_catalog_content`) содержит основные карточки фильмов, сериалов и программ.
- Для каждого родительского `content_id` выбирается последняя версия по `start_date`.
- Дочерний уровень (`msp_ref_child_catalog_content`) содержит эпизоды или дочерние элементы с `content_id` и `top_parent_id`.
- `FULL JOIN` сохраняет как родительские карточки без дочерних записей, так и дочерние записи без корректно найденного родителя.
- Для дочерней строки итоговый `content_id` - это `childs.content_id`, а `top_parent_id` указывает на родительскую карточку.
- Для родительской строки без child итоговый `content_id` - это `parents.content_id`, а `top_parent_id` равен `parents.content_id`.

Связь parent/child в витрине нужна, чтобы VOD-сессии по эпизодам можно было агрегировать до сериала или родительской карточки через `top_parent_id`.

## Производные признаки

- Категория контента берется из поля `type`. В текущих данных: `series` - 33 223 строки, `program` - 6 086, `movie` - 3 659, пустой тип - 1 189.
- Качество структуры каталога рассчитывается в `data_quality` через правила parent/child-объединения.
- Принадлежность к библиотекам берется из `library`. Самые крупные библиотеки: `AMEDIATEKA` - 14 513 строк, `PREMIER` - 10 316, `Birge VOD` - 6 399, `viju` - 5 790, `Freedom Media` - 5 323.
- Принадлежность к студиям/production-группам берется из `production`. По regex-проверке в `production`: HBO/HBO Max встречается в 8 016 строках, Warner - в 1 274, Paramount - в 2 813.
- В доступной логике `vw_full_catalog` нет regex-классификации студий или библиотек: поля `library` и `production` переносятся из родительского каталога. Если нужна отдельная BI-классификация HBO, Warner и др., ее нужно делать downstream через правила по `production`/`library`, например `production ~* 'HBO|Warner|Paramount'`.

## Проверки качества данных

- Дубликаты `content_id`: 0; `content_id` уникален в 44 157 строках.
- Пропуски `content_id`: 0.
- Пустой `original_title`: 2 765 строк.
- Пустой `content_title_ru`: 1 190 строк.
- Пустой `type`: 1 189 строк.
- Пустой `countries`: 4 430 строк.
- Пустой `library`: 1 189 строк.
- Пустой `production`: 13 553 строки.
- `data_quality`: `normal` - 42 937 строк, `child_without_id_parent` - 1 189, `parent_without_child` - 31.
- `top_parent_id` пустой в 1 189 строках; это совпадает с проблемной категорией `child_without_id_parent`.
- Дочерних строк, где `top_parent_id <> content_id`, 39 278.
- `episode` и `season` заполнены в 40 467 строках.

Неконсистентность жанров и тем в самой `spark_dm.full_catalog` проверить нельзя: фактическая схема витрины не содержит `genres` и `themes`, хотя эти поля есть в исходных catalog-объектах.

## Ограничения

- В локальном репозитории не найден SQL-скрипт создания `spark_dm.full_catalog`; логика описана по DB view `spark_bsns_vlt.vw_full_catalog`.
- В итоговой витрине отсутствуют `genres` и `themes`, поэтому для анализа жанров нужно использовать другой catalog-объект или расширять витрину.
- Метаданные неполные: есть пустые названия, страны, production и типы.
- Parent/child-структура не идеальна: есть записи `child_without_id_parent` и `parent_without_child`.
- `library` и `production` переносятся из родительского каталога и могут содержать разные написания брендов/студий.
- Классификация HBO, Warner, Paramount и других студий не является отдельным расчетным полем витрины; ее нужно делать правилами поверх `production`/`library`.
- Поля рейтингов называются `imdb_raiting`, `kinopoisk_raiting`, `age_raiting`; опечатка в имени поля должна учитываться в SQL.

## Использование в аналитике

Основная связка с VOD-сессиями:

```sql
spark_bsns_vlt.msp_content_session.content_id = spark_dm.full_catalog.content_id
```

Примеры использования:

- анализ просмотров по типу контента через `type`;
- анализ популярности контента через `content_id`, `content_title_ru`, `original_title`;
- агрегация эпизодов до родительского сериала через `top_parent_id`;
- сегментация watch time и sessions по `library`, `production`, `countries`, `year`, `age_raiting`;
- построение продуктовых метрик каталога: просмотры по библиотекам, доля сериалов/фильмов, популярность production-групп;
- обогащение пользовательских витрин: в `dwh/datamarts/user_profile.sql` `spark_dm.full_catalog` используется для подтягивания `content_title_ru` к первому и последнему VOD-просмотру пользователя.

Для анализа жанров нужно дополнительно подключать источник, где есть `genres`/`themes`, например catalog source/view из `spark_bsns_vlt`, потому что в `spark_dm.full_catalog` этих колонок нет.

# spark_dm.user_watch_sub_promo

## Назначение таблицы

`spark_dm.user_watch_sub_promo` - пользовательская витрина с верхнеуровневым профилем пользователя Freedom Media. Она объединяет регистрацию, провайдера, первую валидную подписку, промокод на дату первой подписки, демографические признаки из платежных данных и агрегированные признаки просмотра VOD/TV.

Витрина нужна как быстрый базовый слой для исследований пользователей: сегментации, регистрационных и подписочных воронок, retention/churn/reactivation-анализа, анализа trial/promo/paid-подписок, промокампаний, факта просмотра контента и подготовки аудиторий для CVM.

SQL формирования находится в `dwh/datamarts/user_profile.sql`.

## Гранулярность

Одна строка = один пользователь (`user_id`).

По фактической проверке в таблице 1 256 407 строк и 1 256 407 уникальных `user_id`, дублей по пользователю нет. Пользователь может быть в витрине без подписки, без промокода или без просмотра: соответствующие поля будут `NULL`.

## Источники и логика формирования

### Просмотры

CTE `all_sessions` объединяет:

- `spark_bsns_vlt.msp_content_session` - VOD-сессии;
- `spark_bsns_vlt.msp_ref_tv_session` - TV-сессии, где время сессии сдвигается на `+ interval '2 hour'`.

Для всех сессий рассчитывается длительность в секундах. Далее `all_sessions_agg` оставляет только просмотры с `duration_s > 0`, агрегирует их до уровня `dt, user_id, id, title, content_type, device_type, video_type` и оставляет только агрегаты с суммарной длительностью не меньше 120 секунд.

Из этих данных рассчитываются:

- первый значимый просмотр пользователя (`first_session`);
- последний значимый просмотр пользователя (`last_session`);
- суммарное время просмотра за всю историю, последние 30 дней и последние 7 дней;
- количество уникальных просмотренных `id` за последние 30 и 7 дней.

Для VOD-просмотров названия первого и последнего контента обогащаются через `spark_dm.full_catalog.content_id`.

### Подписки

CTE `filtred_sub` берет подписки из `spark_bsns_vlt.msp_ref_subscriptions` и применяет фильтры качества:

- исключает служебные/тестовые пакеты `packet_id not in (1, 2, 3, 5, 6, 8, 11, 13, 15, 17, 18, 19, 53, 55, 63, 67, 68, 69, 70)`;
- исключает тестовых/служебных провайдеров `provider_id not in (2, 3, 5, 6, 7, 44, 42, 45)`;
- исключает подписки с нулевой длительностью `end_date::date - start_date::date != 0`;
- исключает пользователей с `user_role = 'test'` и тестовыми `provider_name` из `msp_ref_users`.

Для пользователя выбирается первая валидная подписка (`sub_num = 1`). По ней в витрину попадают дата первой подписки, максимальная дата окончания подписки пользователя, тип первой подписки, пакет, провайдер и нормализованный источник.

`f_subscription_type` рассчитывается так:

- `promo` -> `Promocode`;
- `trial` -> `Trial`;
- все остальные типы -> `Payment`.

`f_source` и `reg_provider_id` нормализуются по `packet_id` и провайдеру. Например, часть пакетов относится к `Stand Alone`, `Telecom`, `Super App`, `Friends`, `Amediateka`, `All Line`.

### Промокоды

Промокоды берутся из `spark_bsns_vlt.msp_promo_fer_act`. В витрину попадает промокод, который:

- относится к тому же `user_id`;
- активирован в дату первой подписки пользователя с поправкой `(activated_at - interval '1 hours')::date`;
- не содержит `test` или `тест` в `promo_title`;
- не относится к тестовому пользователю или тестовому провайдеру.

Если у пользователя несколько промокодов в один день, выбирается первый по `activated_at`.

### Регистрации

Регистрации берутся из `spark_bsns_vlt.msp_ref_users`. В расчете исключаются тестовые пользователи и тестовые/служебные провайдеры. Для каждого `user_id` выбирается первая регистрация по `registration_dt`.

Далее регистрации соединяются с первой подпиской через `full join` по `user_id`, чтобы сохранить пользователей, которые есть только в регистрации или только в подписках. В итоговый результат попадают только строки, где найден телефон: `coalesce(u.phone, sb.phone) is not null`.

### Пол и возраст

Пол и дата рождения рассчитываются из платежной таблицы `spark_bsns_vlt.msp_ref_pay_transactions` по `param3` для строк `merchant_id = 563748`, где заполнены `user_phone` и `param3`. Расчет основан на разборе цифр `param3`, поэтому эти поля нужно считать производными и использовать с осторожностью.

## Основные сценарии использования

- базовый профиль пользователя и его регистрационные атрибуты;
- сегментация пользователей по провайдеру регистрации и источнику первой подписки;
- анализ регистраций по дням, провайдерам и ролям;
- анализ пользователей с первой, активной или исторической подпиской;
- разделение пользователей на trial, promo и paid-сегменты;
- churn, retention и reactivation на верхнем уровне пользователя;
- анализ использования промокодов на первой подписке;
- анализ факта и давности просмотра контента;
- построение маркетинговых и продуктовых воронок;
- подготовка аудиторий для CVM, реактивации и промо-коммуникаций.

## Ключевые группы полей

### Пользовательские поля

- `user_id` - основной ключ пользователя.
- `registration_dt`, `reg_date` - дата и время регистрации, дата регистрации для когорт.
- `phone` - персональные данные, технически используется для связок, не выводить в отчеты.
- `registration_provider`, `reg_provider_id` - провайдер регистрации и нормализованный провайдер/источник.
- `user_role` - роль пользователя после исключения тестовых ролей.
- `birthdate`, `age`, `gender` - демографические признаки, рассчитанные из платежных данных.

### Поля подписок

- `first_sub_dt` - дата первой валидной подписки.
- `last_sub_dt` - дата окончания последней валидной подписки пользователя.
- `f_duration` - длительность первой валидной подписки.
- `platform_type` - исходный тип первой подписки.
- `f_subscription_type` - укрупненный тип первой подписки: `Trial`, `Promocode`, `Payment`.
- `f_source` - нормализованный источник первой подписки.
- `f_packet`, `f_packet_id` - пакет первой подписки.
- `f_provider`, `f_provider_id` - исходный провайдер первой подписки.

### Поля промокодов

- `promo_title` - промокод, найденный на дату первой подписки.
- `marketing` - маркетинговая кампания/атрибут промокода.

В таблице нет отдельной даты применения промокода: она используется в расчете как `(activated_at - interval '1 hours')::date`, но в итоговую витрину не выводится.

### Поля просмотров

- `first_view_dt`, `first_view_id`, `first_title`, `first_view_device_type`, `first_view_video_type` - первый значимый просмотр.
- `last_view_dt`, `last_view_id`, `last_title`, `last_view_device_type`, `last_view_video_type` - последний значимый просмотр.
- `total_watch_sec` - суммарное время просмотра за всю историю.
- `watch_sec_30d`, `unique_id_30d` - активность за 30 дней.
- `watch_sec_7d`, `unique_id_7d` - активность за 7 дней.

### Технические поля

- `t_v_crdate` - дата создания/обновления записи витрины.

## Ключевые поля для аналитики

- `user_id` - ключ пользователя.
- `reg_date`, `registration_dt` - регистрационные когорты.
- `registration_provider`, `reg_provider_id` - провайдер регистрации/нормализованный источник.
- `f_provider`, `f_provider_id`, `f_source` - провайдер и источник первой подписки.
- `first_sub_dt` - дата первой валидной подписки.
- `last_sub_dt` - дата окончания последней валидной подписки; активная подписка обычно `last_sub_dt >= current_date`.
- `platform_type`, `f_subscription_type` - тип первой подписки.
- `f_packet`, `f_packet_id` - пакет первой подписки.
- `promo_title`, `marketing` - использование промокода на первой подписке.
- `first_view_dt`, `last_view_dt`, `total_watch_sec`, `watch_sec_30d`, `watch_sec_7d` - факт, давность и объем просмотра.

## Фильтры для аналитических запросов

Витрина уже исключает часть тестовых и служебных данных:

- пользователей с `user_role = 'test'`;
- провайдеров `Freedom Telecom (test)`, `Сертификация приложений`, `Провайдер для тестов`, `Тест Setanta + Netflix`, `Закрытые показы`, `140 ball`, `Fmedia`, `Коммерческая витрина`;
- служебные `packet_id` и `provider_id` в подписках;
- подписки с нулевой длительностью;
- промокоды, где `promo_title` содержит `test` или `тест`;
- просмотры короче 120 секунд на уровне агрегата контент/день/устройство.

Типовые фильтры поверх витрины:

```sql
where reg_date between date '2026-01-01' and date '2026-01-31'
```

```sql
where first_sub_dt is not null
```

```sql
where last_sub_dt >= current_date
```

```sql
where promo_title is not null
```

```sql
where first_view_dt is not null
```

Для пользователей без подписки поля `first_sub_dt`, `last_sub_dt`, `platform_type`, `f_subscription_type`, `f_packet`, `f_provider` будут `NULL`. Для пользователей без просмотров поля `first_view_*`, `last_view_*` и watch-time поля будут `NULL`.

## Связь с другими таблицами

### `spark_bsns_vlt.msp_ref_users`

Основная связь по `user_id`. Витрина берет отсюда регистрацию, телефон, провайдера регистрации и роль пользователя. Внутри расчета выбирается первая запись пользователя по `registration_dt`.

Ограничение: тестовые и служебные провайдеры исключаются до попадания в витрину. Если нужна полная сырая история регистраций, нужно обращаться к source-таблице.

### `spark_bsns_vlt.msp_ref_subscriptions`

Связь по `user_id`; в витрине хранится только первая валидная подписка и максимальная дата окончания подписки пользователя после фильтров. Для детального анализа всех подписок, продлений и пауз нужно использовать `msp_ref_subscriptions` или `spark_dm.subscriptions_with_revenue`.

Ограничение: `f_provider`, `f_packet`, `platform_type` относятся к первой валидной подписке, а `last_sub_dt` - к последней дате окончания среди валидных подписок.

### `spark_bsns_vlt.msp_promo_fer_act`

Связь по `user_id` и дате первой подписки: `first_sub_dt = (activated_at - interval '1 hours')::date`. В витрину попадает только первый промокод пользователя за эту дату.

Ограничение: промокоды, примененные не в дату первой подписки, в этой витрине не отражаются.

### `spark_bsns_vlt.msp_content_session`

VOD-просмотры связываются по `user_id`. Идентификатор контента попадает в `first_view_id`/`last_view_id`, если первый или последний просмотр был VOD.

Ограничение: учитываются только значимые просмотры после агрегации с порогом 120 секунд.

### `spark_bsns_vlt.msp_ref_tv_session`

TV-просмотры связываются по `user_id`; `channel_id` используется как `id`, `channel_title` как title, а `video_type = 'tv'`. Время TV-сессии в расчете сдвигается на 2 часа.

Ограничение: `first_view_id`/`last_view_id` для TV - это канал, а не VOD-контент.

### `spark_dm.full_catalog`

Связь для VOD-названий:

```sql
first_view_id = spark_dm.full_catalog.content_id
and first_view_video_type = 'vod'
```

Аналогично для `last_view_id`. Каталог используется только для подтягивания `content_title_ru`; для TV title берется из TV-сессий.

### `spark_bsns_vlt.msp_ref_pay_transactions`

Используется для расчета `birthdate`, `age`, `gender` по телефону и `param3`, только для `merchant_id = 563748`.

Ограничение: это не платежная аналитика и не расчет выручки. Для анализа оплат использовать платежные витрины отдельно.

## Особенности и ограничения

- Таблица агрегирована до уровня пользователя и удобна для верхнеуровневого анализа, но не заменяет детальные таблицы подписок, платежей и просмотров.
- Пользователь может быть зарегистрирован, но не иметь подписки: подписочные поля будут `NULL`.
- Пользователь может иметь подписку, но не иметь просмотров: поля просмотра будут `NULL`.
- Пользователь может иметь просмотр без валидной подписки в этой витрине.
- `f_*` поля подписки относятся к первой валидной подписке, а не к текущей или последней подписке.
- Отдельного поля активной подписки нет; его нужно рассчитывать как `last_sub_dt >= current_date`.
- `last_sub_dt` - максимальная дата окончания валидной подписки, а не дата старта последней подписки.
- Провайдер регистрации и провайдер первой подписки могут отличаться.
- `reg_provider_id` может браться из первой подписки (`sb.f_id`), если подписка найдена, поэтому он не всегда является прямым маппингом `registration_provider`.
- `promo_title` отражает промокод на дату первой подписки, а не все промокоды пользователя.
- Факт `promo_title is not null` не равен факту платной подписки.
- `first_view_dt` и `last_view_dt` отражают значимые просмотры с порогом 120 секунд, а не любые технические события сессии.
- `age` и `gender` рассчитаны из платежного `param3`; если качество `param3` изменится, эти поля нужно перепроверить.
- Поле `phone` является персональными данными и не должно попадать в отчеты, ноутбуки и широкие аналитические выгрузки.

## Примеры SQL-запросов

### 1. Количество зарегистрированных пользователей по дням

```sql
select
    reg_date,
    count(*) as users_count
from spark_dm.user_watch_sub_promo
where reg_date >= current_date - interval '30 day'
group by reg_date
order by reg_date;
```

### 2. Количество пользователей с подпиской

```sql
select
    count(*) as users_total,
    count(*) filter (where first_sub_dt is not null) as users_with_subscription,
    count(*) filter (where first_sub_dt is null) as users_without_subscription
from spark_dm.user_watch_sub_promo;
```

### 3. Пользователи с активной подпиской на текущую дату

```sql
select
    f_source,
    f_subscription_type,
    count(*) as active_users
from spark_dm.user_watch_sub_promo
where last_sub_dt >= current_date
group by f_source, f_subscription_type
order by active_users desc;
```

### 4. Пользователи, использовавшие промокод

```sql
select
    promo_title,
    marketing,
    count(*) as users_count
from spark_dm.user_watch_sub_promo
where promo_title is not null
group by promo_title, marketing
order by users_count desc;
```

### 5. Пользователи, у которых была подписка, но не было просмотров

```sql
select
    f_source,
    f_subscription_type,
    count(*) as users_count
from spark_dm.user_watch_sub_promo
where first_sub_dt is not null
  and first_view_dt is null
group by f_source, f_subscription_type
order by users_count desc;
```

### 6. Пользователи с просмотром контента

```sql
select
    last_view_video_type,
    last_view_device_type,
    count(*) as users_count,
    sum(total_watch_sec) / 3600.0 as total_watch_hours
from spark_dm.user_watch_sub_promo
where first_view_dt is not null
group by last_view_video_type, last_view_device_type
order by users_count desc;
```

### 7. Сегментация пользователей по провайдеру регистрации и типу подписки

```sql
select
    registration_provider,
    reg_provider_id,
    coalesce(f_subscription_type, 'No subscription') as subscription_segment,
    count(*) as users_count,
    count(*) filter (where first_view_dt is not null) as users_with_view
from spark_dm.user_watch_sub_promo
group by
    registration_provider,
    reg_provider_id,
    coalesce(f_subscription_type, 'No subscription')
order by users_count desc;
```

## Итоговое краткое описание

`spark_dm.user_watch_sub_promo` - витрина уровня пользователя, которая объединяет регистрацию, первую валидную подписку, промокод на дату первой подписки, демографические признаки и агрегированные просмотры. Ее удобно использовать для быстрых пользовательских сегментов, маркетинговых аудиторий, воронок и верхнеуровневого анализа retention/churn. Главные блоки данных: регистрация, подписки, промокоды, просмотры и техническая дата обновления. Важно помнить, что подписочные поля относятся к первой валидной подписке, активность подписки нужно считать через `last_sub_dt >= current_date`, а детальный анализ всех подписок, платежей и просмотров лучше делать по детальным таблицам.

# spark_bsns_vlt.msp_content_session

## Назначение

Таблица содержит VOD-сессии просмотра контента пользователями OTT-сервиса. Используется для анализа просмотров фильмов и сериалов, длительности просмотра, количества сессий, активности пользователей во времени и метрик вовлеченности.

По агрегатной проверке в таблице 12 411 069 строк. Период по `session_start_ts`: с `2024-06-18 10:41:48` по `2026-07-01 23:59:59`.

## Гранулярность

Одна строка = одна VOD-сессия просмотра контента пользователем. Сессия имеет пользователя (`user_id`), контент (`content_id`), время начала (`session_start_ts`), время окончания (`session_end_ts`) и, если поле заполнено, длительность просмотра в секундах (`duration_s`).

## Ключевые поля

- `user_id` - идентификатор пользователя для связи с подписками и агрегации поведения до уровня пользователя.
- `content_id` - идентификатор контента для анализа просмотров фильмов, серий и сериалов.
- `vod_session_id` - идентификатор VOD-сессии; полезен для подсчета сессий, но не является гарантированно уникальным в таблице.
- `session_start_ts` - начало сессии, основное поле для привязки просмотра ко времени и периоду подписки.
- `session_end_ts` - окончание сессии, основное поле для проверки границ сессии и длительности.
- `duration_s` - длительность просмотра в секундах, основное поле для watch time при заполненном значении.

## Поля времени

- `session_start_ts` - дата и время начала VOD-сессии. Это источник истины для календарной даты просмотра, active days, retention и попадания сессии в период подписки.
- `session_end_ts` - дата и время окончания VOD-сессии. Это источник истины для окончания просмотра и проверки корректности периода сессии.
- `t_w_crdate` - техническая дата создания записи в DWH.
- `t_w_loaddate` - техническая дата загрузки записи в DWH.

Длительность просмотра считается по `duration_s` как количество секунд просмотра. Для watch time `duration_s` является основным полем, если оно заполнено и больше 0. Разницу `session_end_ts - session_start_ts` нужно использовать как контроль качества или fallback для строк с пустым `duration_s`, потому что агрегатная проверка показала 171 454 строки, где `duration_s` отличается от разницы timestamps больше чем на 60 секунд.

## Производные метрики

- Watch time в часах: `sum(duration_s) / 3600.0` по строкам, где `duration_s > 0`. Если нужно учитывать строки с пустым `duration_s`, fallback через `extract(epoch from (session_end_ts - session_start_ts)) / 3600.0` применять отдельно и помечать в методологии.
- Количество сессий: `count(*)` либо `count(distinct vod_session_id)`. Из-за дублей `vod_session_id` метод подсчета нужно фиксировать в витрине: в таблице 12 411 069 строк и 11 910 479 distinct `vod_session_id`.
- Количество активных дней: `count(distinct date(session_start_ts))` на уровне `user_id` или нужного сегмента.
- Средняя длительность сессии: `avg(duration_s)` по строкам с `duration_s > 0`; по агрегатной проверке среднее по заполненным значениям около 913.87 секунд.
- Сессии на пользователя: `count(*)` или `count(distinct vod_session_id)` после агрегации до `user_id`.
- Часы просмотра на пользователя: `sum(duration_s) / 3600.0` после агрегации до `user_id`.

## Проверки качества данных

- `duration_s <= 0`: агрегатная проверка показала 0 строк. Минимальное заполненное значение `duration_s` = 1 секунда.
- `duration_s is null`: 3 379 701 строка. Для метрик watch time такие строки нужно либо исключать, либо отдельно досчитывать по timestamps с пометкой в методологии.
- `session_end_ts < session_start_ts`: 1 строка. Такие записи нужно исключать из расчета длительности через timestamps.
- Пропуски в `user_id`: 0 строк. Поле можно использовать для агрегации до пользователя и связи с подписками.
- Пропуски в `content_id`: 0 строк. Поле можно использовать как основной идентификатор контента.
- Пустой `content_title`: 10 879 349 строк. Для названий контента нужен внешний справочник или отдельная проверка полноты.
- Аномально длинные сессии: 5 355 строк с `duration_s > 6 часов`, 4 380 строк с `duration_s > 24 часа`; максимальное `duration_s` = 692 398 секунд. Для engagement-метрик рекомендуется каппинг или отдельная фильтрация длинных сессий.
- Дубли `vod_session_id`: 494 629 идентификаторов встречаются больше одного раза, всего 995 219 строк с повторяющимися `vod_session_id`, максимум 3 строки на один `vod_session_id`. Для уникального подсчета сессий нужно определить правило дедупликации.

## Ограничения

- Возможны дубликаты сессий по `vod_session_id`; простой `count(*)` считает строки, а не обязательно уникальные пользовательские сессии.
- Сессии могут прерываться, возобновляться или дробиться на несколько записей, поэтому серия коротких сессий не всегда означает несколько осознанных просмотров.
- `duration_s` не заполнено в части строк и иногда расходится с разницей `session_end_ts - session_start_ts`; источник истины для watch time нужно фиксировать в каждом расчете.
- Очень длинные сессии могут быть фоновым воспроизведением, ошибкой завершения сессии или особенностью устройства.
- Поведение и точность фиксации событий могут отличаться между `phone`, `tv`, `stb`, `pc` и `tablet`.
- `origin_ip` и `device_id` не должны выводиться в отчетах как значения; использовать только в агрегированном или техническом контексте при наличии прав доступа.
- `content_title` неполный, поэтому для контентной аналитики основным ключом должен быть `content_id`.

# spark_bsns_vlt.msp_ref_catalog_content

## Назначение

`spark_bsns_vlt.msp_ref_catalog_content` - основной source-слой метаданных каталога контента OTT-сервиса. Таблица содержит родительские карточки фильмов, сериалов и программ: названия, тип контента, жанры, темы, страны, библиотеку, production, рейтинги, описания, период доступности и технические поля загрузки.

Таблица используется для обогащения VOD-сессий, построения каталожных витрин и аналитики по типам контента, жанрам, странам, библиотекам и производителям. Это родительский источник для `spark_dm.full_catalog`; дочерние элементы каталога связываются с ним через `spark_bsns_vlt.msp_ref_child_catalog_content`.

По агрегатной проверке в таблице 6 280 строк и 5 980 уникальных `content_id`.

## Гранулярность

Одна строка = версия родительской карточки контента.

`content_id` не уникален в таблице: найдено 295 `content_id`, которые встречаются больше одного раза, всего 595 строк в дублях, максимум 3 строки на один `content_id`. В витрине `full_catalog` для родительского каталога выбирается последняя версия по `start_date` через `row_number() over (partition by content_id order by start_date desc)`.

Таблица описывает родительский уровень каталога: фильм, сериал, программу или другую основную карточку. Эпизоды и дочерние элементы находятся в `spark_bsns_vlt.msp_ref_child_catalog_content` и связываются с этой таблицей через `top_parent_id`.

## Структура контента

`msp_ref_catalog_content` хранит родительский уровень каталога. В самой таблице нет полей `parent_id`, `top_parent_id`, `season` или `episode`, поэтому иерархия сериал -> сезон -> эпизод напрямую в ней не описана.

Иерархия собирается вместе с `spark_bsns_vlt.msp_ref_child_catalog_content`:

- `msp_ref_catalog_content.content_id` - родительская карточка фильма, сериала или программы.
- `msp_ref_child_catalog_content.top_parent_id` - ссылка дочернего элемента на родительскую карточку.
- `msp_ref_child_catalog_content.content_id` - идентификатор дочерней единицы, например эпизода.
- В child-таблице есть признаки сезона и эпизода; они используются в `spark_dm.full_catalog`.

По проверке связей: в child-каталоге 47 816 уникальных дочерних `content_id` и 2 226 уникальных `top_parent_id`; все 2 226 `top_parent_id` найдены среди `content_id` родительского каталога.

## Поля классификации

- `genres` - тип `text`, не массив. Множественные значения записываются строкой через `;`. В 4 570 строках есть `;`. Примеры агрегированных значений: `Документальный`, `Комедия`, `Спорт; Единоборства`, `Драма`, `Драма; Комедия`.
- `themes` - тип `text`, не массив. Множественные значения записываются строкой через `;`. В 2 354 строках есть `;`. Примеры агрегированных значений: `Недавно добавлено`, `Взаимоотношения`, `Новые фильмы`, `События; Взаимоотношения; Жизнь; Судьба; Трудности`.
- `countries` - тип `text`, не массив. Множественные значения записываются строкой через `;`. В 1 725 строках есть `;`. Примеры агрегированных значений: `США`, `Россия`, `Великобритания`, `Франция`, `Казахстан`, `Қазақстан`, `США; Соединенные Штаты`.
- `library` - тип `text`, одно текстовое значение библиотеки. Основные значения: `Freedom Media` - 1 630 строк, `AMEDIATEKA` - 1 590, `viju` - 1 508, `PREMIER` - 806, `Birge VOD` - 443.

Для аналитики по жанрам, темам и странам нужна нормализация: split по `;`, trim, приведение регистра, маппинг синонимов и языковых вариантов. Например, в `genres` встречаются `Драма` и `драма`, а в `countries` - `Казахстан`, `Қазақстан` и `Казахстан; Қазақстан`.

## Проверки качества данных

- `content_id is null`: 0 строк.
- Дубликаты `content_id`: 295 значений встречаются больше одного раза, 595 строк в дублях, максимум 3 строки на один `content_id`. Это похоже на версионность карточек, поэтому в витринах нужно выбирать актуальную версию.
- Пустой `content_title_ru`: 1 строка.
- Пустой `original_title`: 184 строки.
- Пустой `genres`: 354 строки.
- Пустой `themes`: 3 590 строк.
- Пустой `countries`: 465 строк.
- Пустой `library`: 0 строк.
- Пустой `production`: 1 736 строк.
- `start_date is null`: 251 строка.
- `end_date is null`: 251 строка.
- `end_date < start_date`: 0 строк.
- Неконсистентность жанров: поле строковое, есть различия регистра и составные значения через `;`, поэтому прямой group by по `genres` дает не нормализованный результат.
- Неконсистентность стран: есть русские и казахские варианты названий, а также синонимы вроде `США` и `Соединенные Штаты`.

## Ограничения

- `content_id` не уникален на уровне таблицы; это source-слой с версиями карточек.
- Жанры, темы, страны, актеры и их id хранятся как текстовые поля, а не нормализованные массивы или связи many-to-many.
- Возможны ошибки регистра, синонимы и разные языки в `genres`, `themes`, `countries`, `production`.
- Метаданные неполные: особенно `themes`, `production`, `countries`, `original_title`.
- Иерархия сериал -> сезон -> эпизод не хранится полностью в этой таблице; для нее нужен child-каталог.
- Поля рейтингов названы с опечаткой: `imdb_raiting`, `kinopoisk_raiting`, `age_raiting`.
- `library = 'test library'` присутствует в 154 строках; для продуктовой аналитики такие записи могут требовать фильтрации.

## Связь с витриной full_catalog

`msp_ref_catalog_content` является родительским источником для `spark_dm.full_catalog`.

В `spark_bsns_vlt.vw_full_catalog`, на логике которого основана витрина, из этой таблицы берутся поля:

- `content_id`
- `content_title_ru`
- `original_title`
- `content_title_kz`
- `library`
- `year`
- `license_type`
- `age_raiting`
- `type`
- `kinopoisk_id`
- `imdb_id`
- `kinopoisk_raiting`
- `imdb_raiting`
- `rights_holder`
- `production`
- `countries`
- `has_trailer`

Трансформации:

- Для каждого `content_id` выбирается последняя запись по `start_date`: `row_number() over (partition by content_id order by start_date desc) = 1`.
- Родительские записи объединяются с `msp_ref_child_catalog_content` через `FULL JOIN` по `parents.content_id = childs.top_parent_id`.
- В итоговой витрине `content_id` может быть дочерним `content_id`, а `top_parent_id` указывает на родительский `content_id`.
- `genres` и `themes` есть в source-таблице и промежуточных catalog-объектах, но в фактической `spark_dm.full_catalog` отсутствуют.
- `data_quality` в `full_catalog` рассчитывается по результату parent/child-объединения.

## Использование в аналитике

С VOD-сессиями таблица используется через каталожную витрину или напрямую по `content_id`.

Основные сценарии:

- обогащение `spark_bsns_vlt.msp_content_session` метаданными контента через `content_id`;
- анализ просмотров по жанрам: split и нормализация `genres`, затем агрегация watch time и sessions;
- анализ популярности контента по `content_id`, `content_title_ru`, `original_title`;
- сегментация пользователей по типу контента (`type`), библиотеке (`library`), стране (`countries`) и production;
- построение витрин наподобие `spark_dm.full_catalog`, где parent-карточки объединяются с эпизодами и становятся удобными для BI.

Для точного анализа эпизодов и сериалов лучше использовать `spark_dm.full_catalog` или join с `msp_ref_child_catalog_content`, потому что `msp_ref_catalog_content` сам по себе хранит только родительские карточки.

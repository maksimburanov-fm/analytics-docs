# MCP-подключение к Greenplum

## Короткий путь

В проекте Greenplum-подключение называется `fmedia_gp`. Название
`freedom_gp` можно использовать в разговоре, но отдельного MCP-сервера с таким
именем нет.

Для обычного входа достаточно:

1. Подключить корпоративный VPN.
2. Запустить Docker Desktop и дождаться готовности движка.
3. Открыть проект `analytics-docs` в Codex.
4. Попросить выполнить через `fmedia_gp`:

   ```sql
   SELECT 1 AS test_connection;
   ```

Если менялась `.codex/config.toml`, нужно перезапустить Codex или открыть новую
задачу.

## Однократная настройка

Строка подключения хранится только в пользовательской переменной среды Windows.
Не записывайте логин, пароль или полный URI в репозиторий.

Пример настройки в PowerShell:

```powershell
[Environment]::SetEnvironmentVariable(
    "DATABASE_URI",
    "postgresql://<user>:<password>@<host>:<port>/<database>",
    "User"
)
```

Если пароль содержит специальные символы, их нужно кодировать по правилам URI.
После настройки выполните:

```powershell
.\.codex\scripts\check-fmedia-gp.cmd -PullImage
```

Последующие проверки выполняются без скачивания образа:

```powershell
.\.codex\scripts\check-fmedia-gp.cmd
```

Скрипт проверяет наличие `DATABASE_URI`, Docker CLI, готовность Docker Engine и
закреплённый образ `postgres-mcp`. Значение `DATABASE_URI` не выводится.

## Как устроен запуск

Проектный файл `.codex/config.toml` переопределяет глобальную настройку
`fmedia_gp` и запускает `.codex/scripts/launch-fmedia-gp.ps1`.

Launcher:

- каждый раз читает свежий `DATABASE_URI` из пользовательской среды Windows;
- проверяет Docker до MCP handshake;
- выдаёт короткую причину ошибки в stderr;
- использует закреплённый digest образа вместо плавающего `latest`;
- запускает сервер только с `--access-mode=restricted`;
- не пишет строку подключения в конфигурацию или логи.

Увеличенный `startup_timeout_sec` отделяет медленный старт Docker от ошибки
MCP handshake. `tool_timeout_sec` даёт аналитическому запросу до 180 секунд, но
не отменяет ограничения read-only режима сервера и требования оптимизировать
тяжёлые запросы.

## Почему раньше возникали ложные ошибки

### Инструмент не появлялся

Если Docker Desktop не был готов или `DATABASE_URI` отсутствовал в окружении
процесса Codex, контейнер завершался до ответа `initialize`. В интерфейсе это
выглядело как пропавший MCP-инструмент или `handshake failed`.

Теперь launcher читает пользовательскую переменную при каждом старте и
проверяет Docker до запуска контейнера.

### `docker run` выглядел зависшим

Команда с `docker run -i` запускает STDIO MCP-сервер и ждёт MCP-клиента.
Отсутствие обычного приглашения командной строки в таком режиме ожидаемо и само
по себе не означает проблему с базой.

### Не работал список MCP resources

`postgres-mcp` предоставляет MCP tools, а не resources. Для проверки нужно
вызывать `fmedia_gp.execute_sql` напрямую с `SELECT 1`, а не начинать с
`list_mcp_resources`.

### Падал большой SQL

Ошибка памяти Greenplum, превышение лимита времени или тяжёлый план выполнения —
это отдельная проблема SQL, а не подключения. Сначала подтвердите соединение
через `SELECT 1`, затем:

- ограничьте исходную когорту до соединений с большими таблицами;
- используйте диапазоны timestamp вместо приведения столбца к `date`;
- возвращайте агрегаты, а не пользовательские строки;
- проверяйте тяжёлый запрос через `EXPLAIN` до выполнения.

## Диагностика

| Симптом | Что проверить |
|---|---|
| `fmedia_gp` отсутствует | Проект доверенный; задача открыта после изменения `.codex/config.toml`; Codex перезапущен |
| `handshake failed` или `initialize response` закрыт | Запустить `check-fmedia-gp.cmd`; проверить Docker Desktop и локальный образ |
| `DATABASE_URI is missing` | Установить переменную на уровне `User`, не добавлять её в файлы проекта |
| Ошибка соединения или timeout | Проверить VPN и доступность узла базы |
| Authentication failed | Обновить пользовательский `DATABASE_URI`; не присылать его в чат |
| `SELECT 1` работает, аналитический SQL падает | Анализировать план, объём данных и Greenplum memory отдельно от MCP |

## Безопасность

- MCP работает в `restricted` режиме.
- Допустимы только read-only запросы.
- Секреты не хранятся в Git.
- Нельзя выгружать персональные данные и списки пользовательских
  идентификаторов.
